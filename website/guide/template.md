# The HTML template

The template is the `index.html` of your build (`dist/index.html` with Vite). The package injects the tags of each page in its `<head>`.

## Where the tags go

If the template contains the `<!--seo-head-->` comment, the tags replace it:

```html
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <!--seo-head-->
  <link rel="stylesheet" href="/app.css" />
</head>
```

Otherwise, they are added just before `</head>`. Change the comment with the [`placeholder`](../reference/options#placeholder) option.

::: tip
Vite keeps HTML comments in the build, so `<!--seo-head-->` is still in `dist/index.html`.
:::

## Default tags in the template

You can keep default tags in `index.html`, for example for local development without the server:

```html
<title>My Store</title>
<meta name="description" content="Jerseys and sportswear" />
<meta property="og:image" content="https://shop.example.com/og-image.jpg" />
```

When a page redefines a tag, the tag of the template is **removed**, so the page never has two titles or two `og:image`. Tags that the page does not redefine are kept.

Tags that can be removed this way:

- `<title>`;
- `<meta name="...">` and `<meta property="...">` with the same name or property as a new tag;
- `<link rel="canonical">`, `<link rel="icon">`, `<link rel="shortcut icon">`;
- `<script type="application/ld+json">` added by the package itself (with the `data-spa-meta-tags` attribute). Your own scripts are never removed.

Everything else is kept: charset, viewport, styles, preload links, analytics scripts, etc. Only the `<head>` is changed, never the `<body>`.

To keep all the tags of the template and only add the new ones, set [`replaceExisting: false`](../reference/options#replaceexisting).

## Write the Twitter tags with `name`

The standard Twitter tags use `name`, not `property`:

```html
<!-- Good -->
<meta name="twitter:title" content="My Store" />

<!-- Not removed when the page sets its own Twitter title -->
<meta property="twitter:title" content="My Store" />
```

The package writes `name="twitter:..."`. A template tag written with `property="twitter:..."` is a different tag for the package, so the page would contain both. Fix your template if it uses `property` for Twitter tags. The same goes for `og:` tags, which use `property`.

## Things to avoid in the template

- **A `>` inside an attribute of a tag that the page redefines**, for example `<meta name="description" content="a > b">`. The package finds tags with a simple pattern that stops at the first `>`, and a piece of the tag would stay in the page. Write `&gt;` instead.
- **Tags inside an HTML comment or a script of the `<head>`**: they are seen as real tags.

These limits come from the fact that the template is processed with fast patterns rather than a full HTML parser, which keeps the package free of dependencies. A normal `index.html` generated by Vite is not affected.
